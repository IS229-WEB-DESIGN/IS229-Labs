Core principle: Accessibility is not an optional add-on; it is part of professional interface quality.
Concept 1

Native HTML

Provides built-in accessibility when used correctly.

Concept 2

Visible focus

Shows keyboard users where interaction currently is.

Concept 3

Failure-path testing

Checks errors and edge cases, not only successful use.

Code explanation

Read the code line by line

Pattern A · css
.skip-link:focus {
  position: static;
  padding: .75rem;
}
Pattern B · html
<label for="destinationSearch">Search destinations</label>
<input id="destinationSearch" type="search">

What it does → Why it works → Where we use it

  1. .skip-link:focus
    Applies the rule when the skip link receives keyboard focus.
  2. position: static
    Returns the focused link to normal page flow so it becomes visible.
  3. <label for=...>
    Gives the search control an accessible visible name.
  4. type="search"
    Communicates the purpose of the control to the browser and assistive technology.

Project connection: This code belongs to the Week 09 Morobe Discover increment and should produce a visible or testable change related to Keyboard support, accessible labels/focus and quality evidence.
