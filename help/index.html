Stuck? Diagnose the evidence.

Use the grouped checks below before random editing. Most front-end problems become easier once you identify whether the issue is structure, style, behaviour, data, path or deployment.

CSS not applying?
  1. Check the stylesheet path and filename.
  2. Inspect the element in DevTools Styles.
  3. Check selector spelling and specificity.
  4. Look for invalid CSS syntax above the broken rule.
  5. Confirm the browser loaded the expected CSS file.
JavaScript not running?
  1. Open the Console and read the first error.
  2. Confirm the script path and defer/loading order.
  3. Check the DOM selector actually matches an element.
  4. Confirm addEventListener is attached to the intended element.
  5. Reduce the function to the smallest working version.
Fetch / JSON failing?
  1. Run the project through a local web server.
  2. Open Network and inspect the request status/path.
  3. Validate the JSON syntax.
  4. Check response.ok before parsing.
  5. Show a user-facing loading/error state.
Git push problem?
  1. Run git status.
  2. Read the exact Git error message.
  3. Pull remote changes if required.
  4. Resolve conflicts deliberately and retest.
  5. Push only after the local state is correct.
GitHub Pages 404?
  1. Confirm Pages is enabled for the intended branch/folder.
  2. Confirm index.html exists in the published location.
  3. Use relative paths appropriate for a project site.
  4. Wait briefly after the first deployment, then refresh.
  5. Open DevTools Network to locate missing assets.
Layout breaks on mobile?
  1. Use responsive mode around the failing width.
  2. Look for fixed widths larger than the viewport.
  3. Check grid/flex wrapping rules.
  4. Make media fluid with max-width:100%.
  5. Add a breakpoint only when the layout genuinely needs it.

Ask yourself

  1. What exactly did I expect?
  2. What actually happened?
  3. Which file owns that behaviour?
  4. What does DevTools show?
  5. What is the smallest test that can prove the cause?
